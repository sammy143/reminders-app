# F005: Appointment storage + list/add/edit screens

## Goal
Create, edit and delete appointments (title, start, travel minutes, in-person, intensity), persisted
across reloads on web and Expo Go. Screens follow docs/design/ (`home.png`, `new-appointment.png`)
and the deviations in docs/design/README.md (harness/feature_list.json F005).

## Approach (layer by layer, per docs/ARCHITECTURE.md)
- **domain/**: `newAppointment(input, id)` defaults, plus form validation as a pure function
  (`validateAppointmentDraft(draft) → errors`): title required and trimmed, travel 0–600 whole
  minutes, buffer 0–120, valid start. No storage or time calls; tests next to it.
- **services/appointmentStore.ts**: AsyncStorage (`@react-native-async-storage/async-storage`) under the key
  `appointments.v1`, holding a JSON array. Parse on load with a **Zod** schema (PRINCIPLES #7): drop invalid
  entries (don't crash), and keep valid ones. Also `save(list)`. Tests use the package's official jest mock.
- **state/appointments.ts**: a Zustand store: `hydrate()`, `add`, `update`, `remove`, `byId`. Every mutation
  persists through the service. `ui/` never imports services (enforced by the architecture check).
- **ui/**: `AppointmentCard`, `AppointmentForm` (in-person toggle, travel and buffer steppers, computed
  leave-by, intensity chips, preview bubble), `IntensityChips`, `Stepper`, `Toggle`, `NagBubble`,
  `Nag` (one simple vector mascot from `nag-irritated.svg`, via react-native-svg), `DateTimeField`.
- **app/** (thin routes): `index.tsx` Today list, `appointment/new.tsx`, `appointment/[id].tsx` (edit and
  delete). The root `_layout.tsx` hydrates the store.

## Decisions
- **Start picker** (2026-09-24): `@react-native-community/datetimepicker` on native, with a
  platform file `DateTimeField.web.tsx` using `<input type="datetime-local">` on web. Both give a local
  Date. It is turned into an ISO string **with offset** (`formatISO` from date-fns) at the state/service
  edge, because F002 requires the offset.
- **IDs**: `expo-crypto` `randomUUID()` in state/ (works in Expo Go).
- **Defaults**: buffer 5 (PLAN), travel 20, inPerson true, intensity `spicy` until Settings (F008) adds a
  default. status `scheduled`, source `manual`, notificationIds `[]`.
- **Home list**: upcoming appointments sorted by start, including those already past today.
  - The card shows the title, "Leave by h:mm · <countdown>", and an in-person/online badge.
  - The countdown comes from `withLines`' cue logic (`formatCue`/`formatStartCue`); when nothing is left, show the start time only.
  - The edge-bar tone comes from the next `buildSeries(appt, now)` step, or `tone-done` / muted when none is left.
  - `now` comes from a small `useNow(intervalMs)` hook in state/.
  - The empty state keeps the current placeholder copy.
- **Home Nag bubble**: shows a line for the next upcoming appointment (via `withLines`), otherwise a
  calm idle line. The mascot has a calm variant only for now; per-tone expressions come with F006.
- **Preview bubble on the form**: the real bank line for the harshest step the chosen intensity reaches,
  i.e. step 6 with its cue ("10 min late"): mild → sarcastic, spicy → savage, savage → unhinged. For
  events that aren't in person, the polite step-1 line with its start cue. Never the mockup's
  placeholder copy (README deviation). (Revised in fix round 1: step 3 was sarcastic at every intensity,
  so every preview looked the same.)
- **Delete**: on the edit screen, an in-screen two-tap confirm ("Delete" → "Tap again to delete"), because
  `Alert` is a no-op on web.
- **Out of scope** (README deviations and later features): Upcoming tab, bottom nav (F008 adds
  Settings), streak pill (F013), "Metro"/"3h buffer", notifications (F006). A plain Stack with a FAB.
- **Fonts**: still system fonts (tech debt from F001); don't load them in this feature.
- Add libraries with `EXPO_OFFLINE=1 npx expo install …` (the sandbox blocks api.expo.dev).

- **Implementation choices not covered above** (2026-09-24, implementer):
  - Domain split: `src/domain/appointment.ts` (draft defaults, validation, `newAppointment`, `applyEdit`,
    `isOffsetDateTime`) and `src/domain/today.ts` (`groupUpcoming`, `cardStatus`, `nextNagLine`,
    `previewLine`). `draftDefaults(now)` starts one hour out, rounded up to 5 min.
  - Steppers move in 5-min steps and clamp to the validation limits; validation still runs on submit.
  - `isOffsetDateTime` is the Zod refinement for `startsAt`: it rejects impossible calendar values
    (`2026-02-30`, `24:00`) that `Date.parse` rolls forward (repays the F002 tech-debt item).
  - The store waits for `hydrate()` before any mutation so an early add can't overwrite stored data.
  - Home list groups by local day: "Schedule" (today, "N remaining"), "Tomorrow", then a date heading.
    An online card's second line is "Online · starts in N min" instead of "Leave by".
  - Home Nag bubble: header "NAG • <TONE> TONE"; its right-hand note is "at h:mm AM" when the next line
    fires later (the line's cue is the one it will carry then, not the live countdown), and is hidden
    when the step is already due. Idle line: "Nothing on the clock. Enjoy it while it lasts."
  - Nag mascot colours: shapes use `fill-*`/`stroke-*` token classes, registered with NativeWind
    `cssInterop` (target `style`, `nativeStyleToProp` fill/stroke). This works on web (react-native-web
    turns the `$$css` style into classes; checked in the DOM). Native is untested in the sandbox.
    Typings for it are in `src/ui/svg-classname.d.ts`.
  - Navigation lives only in routes: screens take callbacks (`onSubmit`, `onCancel`, `onAdd`, `onOpen`),
    and routes close with `router.dismissTo('/')` (pops, or replaces when there's no history after a web
    reload). `scripts/check-architecture.mjs` now rejects `expo-router` imports in `src/ui/`
    (ARCHITECTURE.md updated).
  - Home shows only `scheduled`/`snoozed` appointments (`isActive`); `cardStatus` is `done` and
    `nextNagLine` skips the rest. The Nag bubble uses the step that fires soonest across appointments.
  - Load-time pruning: `prunePast(list, now)` drops appointments from before local midnight today;
    `hydrate()` applies it and saves the result. Invalid stored entries (Zod) and repeated ids (first
    kept) are dropped on load and so disappear from storage on the next save. This is intended.
  - Storage failures: if loading fails, `hydrated` is set with a `loadError` that Home shows
    (non-blocking), and saving is refused until a later load succeeds, so a failed read can't overwrite
    stored data. A failed save leaves state unchanged, and the form shows "Couldn't save. Try again."
  - Double submit: a ref marks a save in flight; both Save buttons are disabled (`aria-disabled`) until
    it settles.
  - Accessibility uses ARIA props (`role`, `aria-label`, `aria-checked`, `aria-disabled`, `aria-hidden`),
    which react-native-web 0.21 puts in the DOM and React Native maps natively; `accessibilityState` is
    not forwarded on web. The toggle is `role="switch"`, and the chips are `role="radio"` inside a
    `radiogroup`. Nag is decorative (`aria-hidden`). A card's label reads title, badge, cue line and
    start time.
  - Jest runs in `America/Los_Angeles` (`jest.global-setup.js`), a stricter check than the machine's zone.
    A sanity test asserts the offset changes across 2026-11-01, when DST ends, and there are DST tests for
    the ISO offset and for `groupUpcoming`.
  - Jest: `jest.setup.ts` loads the official AsyncStorage mock and maps `expo-crypto.randomUUID` to
    Node's crypto (jest-expo stubs the native module to return undefined).

## Deviations from the mockups / plan
- **Location row omitted** from the form: `Appointment` has no location field and PLAN v1 enters travel
  manually. It can come back with a maps feature.
- **Card subline**: "Leave by h:mm" is muted, and only the countdown takes the tone colour (DESIGN.md).
- **Countdown for far events** reads in raw minutes ("starts in 1560 min"), because the plan says to
  reuse `formatCue`/`formatStartCue` as they are. Logged in docs/tech-debt.md.
- **Preview bubble** has no timestamp on the right (the mockup's "14:56" has no meaning here).
- **Selected chip** uses a 10% tone tint instead of the mockup's `orange-50`, which isn't a token.

## Verify
- Can create, edit, delete an appointment with title, start, travel minutes, in-person, intensity
- Data persists across app reload (web and Expo Go)
- bash scripts/check.sh passes
- Extra: RNTL tests for the form (validation, submit), the store (CRUD + persist), the service (corrupt
  storage → valid entries kept); a Playwright web flow: create → reload → still there → edit → delete →
  reload → gone.
- Expo Go persistence can't run in the cloud sandbox, so that's a manual step for the user (PASS-PENDING-HUMAN).
