# F008: Settings: default intensity, buffer minutes, mute today

## Goal
A Settings screen (design `settings.png`) where the user sets the default intensity and buffer for new
appointments and can "mute today" (PLAN rule 5): cancel today's nags and schedule none until midnight.
See harness/feature_list.json F008.

## Approach
- **types/**: `Settings { defaultIntensity: Intensity; defaultBufferMinutes: number; mutedUntil: string | null }`.
  `mutedUntil` is an ISO string with an offset.
- **domain/settings.ts** (pure, `now` injected):
  - `DEFAULT_SETTINGS`: spicy, 5 min, not muted.
  - `muteUntilMidnight(now)`: the next local midnight, computed with local calendar arithmetic (DST-safe).
  - `isMuted(settings, now)`.
  - The new-appointment draft takes its intensity and buffer defaults from settings.
    `DRAFT_DEFAULTS` stays for everything else. Editing an existing appointment doesn't change it.
- **domain/notificationPlan.ts**: `planNotifications(…, { mutedUntil })` drops every planned notification
  whose `at < mutedUntil` while muted. Tomorrow's notifications (at or after midnight) are still planned.
  - Result: muting cancels today's pending nags on the next sync. The series resumes after midnight
    (the foreground top-up, plus notifications for times after midnight that were never dropped).
  - Unmuting re-plans the remaining future steps. A due step never re-fires, because it isn't a save.
- **services/settingsStore.ts**: AsyncStorage key `settings.v1`, parsed with Zod at the boundary. Invalid or
  missing data falls back to the defaults field by field. An expired `mutedUntil` counts as unmuted.
- **state/settings.ts**: a Zustand store with `hydrate`, `setDefaultIntensity`, `setDefaultBuffer`, `muteToday` and `unmute`.
  Each saves, then applies (the existing pattern). Mute and unmute trigger a notification sync. The
  appointments store's sync reads `mutedUntil` from the settings store, so sync inputs come from state/, never ui/.
- **ui/SettingsScreen.tsx** (from `settings.png`):
  - Default meanness: the existing `IntensityChips`.
  - Buffer: the existing `Stepper`, within the domain limits.
  - "Mute today": the existing `Toggle`, ink colour when on. The subtitle reads "Nag stays quiet until midnight" when muted.
  - Real copy only.
- **Home**: when muted, a small non-blocking banner, "Muted until midnight", with an "Unmute" action.
- **Navigation**: README says v1 has Today and Settings only, so a bottom tab bar with Today and Settings
  goes in an expo-router group `(tabs)`. `appointment/*` and `alarm/*` stay as stack screens on top.
  - Update `scripts/check-architecture.mjs` `routeExists` so route groups (`(tabs)/`) resolve.
    Otherwise `'/'` and `'/settings'` would be flagged. Add a probe test in a scratch copy.
- **Out of scope** (README deviations and later features): supportive-mode row, calendar row (F011),
  home location row (F012), "Emergency escalation", version badge.

## Decisions
- **"Today" means until the next local midnight** (2026-09-25). Mute drops nags firing before then, for every
  appointment, including a late-night event's series. An event just after midnight still nags.
- **Mute is stored**, so it survives an app restart. It expires by time, with nothing to clean up: `isMuted` compares with `now`.
- **Defaults apply to new appointments only** (2026-09-25).
- **Tabs** per the README "Today + Settings" (2026-09-25).
- **Implementation choices and deviations** (2026-09-25, implementer):
  - **Plan option shape:** `planNotifications(list, now, justSaved, { limits, mutedUntil })`. The 4th
    parameter became an options object (the two `limits` call sites in tests updated). A notification is
    dropped when its *clamped* time (`max(at, now + 5 s)`, rounded up to a second) is before `mutedUntil`,
    so a just-saved appointment's due step never fires while muted. Messages are filtered after
    `withLines`, so the kept lines (tomorrow's) are the same as unmuted and the diff never re-words them.
    An appointment with nothing left after the filter takes no series slot (the next one gets it).
  - **Imminent nags while muted:** `syncNotifications(port, list, now, justSaved, mutedUntil)` passes an
    empty `keepImminentFor` while muted, so a nag about to fire is cancelled too.
  - **Sync wiring without a state/ cycle:** `state/settings.ts` imports nothing from `appointments.ts`.
    `appointments.ts` reads `activeMute(useSettings.getState().settings, now)` in `runSync` (after
    `await`ing both hydrations, so a stored mute holds from the first sync after a restart) and subscribes
    to the settings store: a change of `mutedUntil` between two hydrated states requests a sync. Loading
    settings is not a change (the sync already waits for it).
  - **Settings store:** holds `settings: Settings` plus `clock` (default `systemClock`; tests use
    `resetSettingsForTests(clock)`), `hydrated`, `loadError`. Changes go through a promise chain, one at a
    time, each computed from the last applied state. The buffer changes by a delta
    (`adjustDefaultBuffer(±5)`, clamped by `adjustBuffer` in domain), so two quick stepper taps give 15,
    not 10 (fix round 1). `mutedUntil` is `formatISO(muteUntilMidnight(now))`.
  - **Load failure** (fix round 1, replaces "saves still allowed"): same rule as the appointments store.
    While `loadError` is set, Settings shows "Couldn’t load your settings. Try again." and the defaults, and
    every change is refused (it retries the load first; if that works, the change applies on top of the
    stored settings). Defaults are never saved over stored settings.
  - **Sync with unreadable settings** (fix round 1): `runSync` skips (leaves the OS as it is) while the
    settings `loadError` is set, because an unknown mute is not "not muted". The next sync (foreground or
    any change) retries the load.
  - **Stale load after a save** (fix round 1): not reachable, so no generation counter was added (it would
    be dead code). Every change awaits the same `hydrate()` promise before reading state, and a successful
    load is never repeated (`hydrating` is kept), so a load can't finish after a save. A failed load
    applies no settings, and changes are refused until a load succeeds. A test checks the invariant: a load
    held in flight, a save made meanwhile, and the saved value wins, in state and in storage.
  - **New-appointment form:** `draftDefaults(now, appointmentDefaults(settings))`. `ui/NewAppointmentScreen`
    (the route is a thin wrapper; a test file can't live in `src/app/`, Expo Router would bundle it as a
    route) waits for settings to hydrate (a web reload lands on `/appointment/new` first), shows a blank
    screen meanwhile, then takes the defaults once. Its clock is the appointments store's.
  - **Tabs:** `expo-router/js-tabs` (`Tabs` from the root export is deprecated) with a custom `tabBar`
    that renders `ui/components/TabBar.tsx`, so colours stay NativeWind tokens (the stock bar takes colour
    values). Icons are small inline SVGs (no icon font in the app); the SVG `cssInterop` registration moved
    from `Nag.tsx` to `ui/components/svgInterop.ts` so both use it.
  - **Checker:** `routeExists(appDir, route)` moved to `scripts/routes.mjs` (the app dir is a parameter,
    so only the test passes another one). It walks path segments and enters route groups at every level; an
    explicit group segment (`'/(tabs)/settings'`) also resolves; names starting with `_` or `+`
    (`_layout`, `+not-found`, `+html`) never match (fix round 1). The first scratch probe became
    `scripts/routes.test.mjs` (`node --test`, fixtures in `scripts/__fixtures__/app/`): the good literals
    pass; `/nope`, `/tabs/settings`, `/(tabs)/nope`, `/(auth)`, `/appointment`, `/settings/more`, `/_layout`,
    `/+not-found`, `/+html` fail. `scripts/check.sh` runs it as a new "checker tests" step. This only adds to
    the gate; nothing was loosened. Mutation-checked: disabling the group or `_`/`+` rules fails a test.
  - **Design deviations (settings.png):** no version badge, supportive-mode, calendar, home-location or
    emergency rows, and no "Nag v1.2.0" footer line (README). The avatar is the one `Nag` mascot, tinted by
    the chosen default meanness. The buffer hint says "Extra slack before you have to leave" instead of
    "Arrival countdown margin" (buffer is slack before leave-by, not an arrival countdown). Added a caption
    "New appointments start with these. Existing ones keep their own." The buffer uses the existing
    `Stepper` (round buttons, now with an optional `hint`), not the mockup's boxed pill. Chips keep the
    existing "Selected" badge.
  - **Home banner:** "Muted until midnight" with an "Unmute" text button (44 px target) in the same neutral
    bordered box as the notifications-off banner, above it. A failed unmute says so in the banner.
  - **Home Nag bubble while muted** (fix round 1): `nextNagLine(list, now, mutedUntil)` skips lines that
    fire before the mute ends. If one remains (tomorrow's), it is shown with its "at h:mm". Otherwise the
    bubble says "Muted until midnight. Enjoy the quiet." (heading "Muted"), which is calm copy, not a bank
    line.
  - **Mute switch copy** (fix round 1): off "Silence Nag until midnight", on "Nag stays quiet until midnight".

## Verify
- Settings persist; new appointments use defaults
- Mute today cancels today's series and suppresses scheduling until midnight
- bash scripts/check.sh passes
- Extra tests:
  - Domain: midnight across DST (America/Los_Angeles, 2026-11-01), with isMuted before and after midnight.
  - Plan: drops `at < mutedUntil` and keeps tomorrow's notifications.
  - Store: the fake port shows today's pending cancelled on mute and re-planned on unmute, with no due re-fire.
  - Settings store: persistence, and corrupt data falls back to defaults.
  - Form: defaults prefilled.
  - Web smoke:
    - Change the defaults, reload: they're kept. A new appointment form shows the new defaults.
    - Mute, reload: the "Muted until midnight" banner is still there. Unmute: the banner goes.
  - The tab bar works.
- Device check needed (real notifications cancelled and restored).
