# F004: Insult bank and line selection (character voice, unique per series, practical cue)

## Goal
A hardcoded bank of lines in Nag's voice plus pure selection that turns `buildSeries` output into
messages with `text` (harness/feature_list.json F004; PLAN product rules 3, 4, 6, 7; DESIGN.md "Voice (Nag)").

## Approach
- `src/domain/lines/bank.ts`: data only. `Record<Tone, Record<Intensity, readonly string[]>>`
  covering **every** tone × intensity (including `supportive`, and cells F003 can't reach today:
  F007's snooze and supportive transforms may produce them). Split into several files if one would go over 300 lines.
- Each line is a template containing the `{cue}` placeholder exactly once.
- `src/domain/lines/cue.ts`: `formatCue(minutesFromLeaveBy: number): string`.
- `src/domain/lines/select.ts`: `withLines(series: SeriesStep[], appt: { id: string; intensity: Intensity }): SeriesMessage[]`,
  where `SeriesMessage = SeriesStep & { text: string }` (type in `src/types/`).
- Tests next to each file.

## Decisions
- **Cue format** (2026-09-24): round `minutesFromLeaveBy` to the nearest whole minute (ties go away from zero).
  < 0 → "leave in N min"; 0 → "leave now"; > 0 → "N min late". Singular "1 min". −0.4 → "leave now".
- **Deterministic, unique selection** (2026-09-24): `seed = stableHash(appt.id)` (a small pure string hash,
  such as FNV-1a; no crypto, no Math.random). For a step, the bank cell is (tone, intensity) and `k` is the
  number of *scheduled* steps before it that map to the same cell. Scheduled means from the full
  schedule, not the filtered array, so rebuilding after some steps are dropped gives the same line. Pick
  `cell[(seed + k) % cell.length]`. The result depends only on (id, step, tone, intensity), never on
  the array index. The line index depends only on seed + k, not on `now`.
  - To compute `k` without importing buildSeries internals: count earlier step numbers whose capped
    tone is the same. Expose a small helper from series.ts (for example `scheduledTone(step, intensity)`)
    rather than duplicating the ladder.
- **Minimum lines per cell** (2026-09-24): at least 6 per cell, so no cell ever runs out (mild×sarcastic
  needs 4 today). Lines are unique across the whole bank, so different cells never collide.
- **Content rule** (PLAN rule 3): lines mock the lateness and the situation, never identity, looks,
  ability, or protected traits. No slurs or profanity stronger than mild, even at savage. Voice: deadpan,
  dry, short (DESIGN.md). The lines are Nag speaking; the character's name isn't needed in the text.
- Supportive lines are kind and practical (still with a cue); they aren't insults.
- **Cue placement and capitalisation** (2026-09-24, implementer): one cell can be hit at any offset
  (pulled steps, F007), so every template must read well with all three cue forms. Templates put
  `{cue}` last as its own sentence (`"Move. {cue}."`) or after a colon. `fillCue` capitalises the cue
  at the start of the text or after `.`/`!`/`?`, and leaves it lowercase after `:`. `formatCue` stays lowercase.
- **Helper** (2026-09-24, implementer): `scheduledTone(step, intensity)` exported from series.ts,
  as planned. `withLines` takes `SeriesStep[]` (ladder tones only). Supportive cells exist in the
  bank, but selecting them is F007's job.
- **Lines are position- and cue-neutral** (2026-09-24, fix round 1): any line may fire at any step
  with any cue ("leave in 5 min", "leave now", "5 min late"). Polite lines must also stand alone, since
  a not-in-person event gets exactly one reminder, possibly pulled to `now` after leaveBy, so they never
  promise escalation. No line uses a cue word (leave/now/late/min) outside the cue. No line assumes
  the user can stand or walk a particular way. Enforced by bank.test.ts: cue-word repetition, a
  sequence-word list for polite/firm, and no shared normalised 3-word phrase between lines that can
  fire in one series (all ladder tones at one intensity). The allowlist for that test is empty.
- **Polite lines are about time only; no body words** (2026-09-24, fix round 2): polite is the only
  reminder a video or phone call gets, so polite lines never mention keys/door/shoes/coat/wallet/bus.
  No line anywhere uses walk/feet/foot/stand/run. Cells that fire more than once in a series
  (sarcastic × mild, savage × spicy) are ordered so neighbouring entries, wrapping round, never make the same joke. Both word rules are enforced
  by tests in bank.test.ts; the neighbour ordering is a manual check.
- **Note for F007** (2026-09-24, fix round 1): `withLines` computes `k` from `scheduledTone`, which
  never returns `supportive`, so supportive steps passed through it would all get k = 0 and repeat a
  line. F007 must compute `k` for supportive steps itself (e.g. count earlier supportive steps in
  the transformed series) instead of reusing `withLines` unchanged.
- Out of scope: Claude-generated lines (v2), the notification title and body layout (F006).

- Unit tests: lines unique within a series; every line includes a minutes/leave cue
- Reviewer confirms no identity/appearance/ability/protected-trait insults
